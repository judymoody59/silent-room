# 1. Close occupant labels to a server-issued animal name set

Date: 2026-09-24

## Status

Accepted

## Context

이 서비스는 자유 텍스트 경로를 두지 않는 것 자체가 정체성이다 (`.ai/project/scope.md`,
`.ai/AI_AGENT.md` 1장). 방 안에서 관찰되는 참가자 라벨도 사람이 쓴 텍스트에 해당하므로,
어떤 형태로 둘지 결정이 필요하다. 결정하지 않으면 라벨 자리가 곧 메시지 필드가 될 수 있다.

### 검토한 대안

| 선택지 | 기각 근거 | 되돌리기 비용 |
|---|---|---|
| (가) 라벨 없이 `occupantId` 를 원시 식별자로만 노출 | 방 안에서 서로 구분·기억이 어렵고, 재실 표시라는 이 이슈의 관찰 목적이 약해진다 | 좁음 — 라벨 배정 규칙을 뒤에서 추가하면 된다 |
| (나) 서버가 폐쇄 집합에서 배정한 값(동물 이름 열거형)을 `occupantId` 로 쓴다 | 채택 | — |
| (다) 클라이언트가 보낸 문자열을 라벨로 수신 | 자유 텍스트를 받지 않는다는 서비스 정체성(`.ai/project/scope.md`)을 뒤집는 범위 밖 결정이다 | 큼 — 저장·검증·전송 경로 전반의 변경이 필요하다 |

## Decision

우리는 방 안에서 관찰되는 참가자 라벨을 **서버가 도메인 열거형에서 배정한 동물 이름**으로
닫는다. 다른 대안은 관찰 목적을 약화하거나(가) 서비스 정체성을 뒤집는(다) 문제가 있어 택하지
않는다.

- 폐쇄 집합은 `domain` 의 열거형으로 두고, 그 값이 곧 `occupantId` 다.
- 같은 방 안에서 한 시점에 유일하다. 새 참가자에게는 그 방에서 미사용 값 중 하나를 배정하고,
  퇴장 시 해당 값은 다시 배정 가능해진다.
- 클라이언트가 이름 문자열을 보내는 경로를 만들지 않는다.

## Consequences

- 라벨 문자열을 받는 엔드포인트·필드가 이 리포에 존재하지 않는다는 규칙(`.ai/AI_AGENT.md` 1장,
  `.ai/project/scope.md`)이 이 이슈의 구현으로도 유지된다.
- 열거형이 방 수용 상한을 실질적으로 정한다. 상한을 늘리려면 열거형에 값을 더해야 하며,
  더 큰 방을 다루려면 별도 이슈에서 `Capacity` 개념 도입과 함께 다시 결정해야 한다.
- 방 안에서 이름이 모두 소진되면 그 방으로의 신규 입장이 거절되어야 한다. 그 정책의 세부는
  후속 이슈에서 정한다 — 이 이슈에서는 관찰 가능한 값의 형태만 확정한다.
- 클라이언트에는 라벨 문자열을 서버로 보낼 수단이 없다는 것이 계약이 된다.
